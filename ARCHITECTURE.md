# Архитектура пилота

```text
Браузер / React
  → Next.js /api: валидация HTTP, адаптация контрактов, единые ошибки
    → backend-client → FastAPI: AI и единственная формула рейтинга
    → task-service → прежний store.ts: задачи и решения по откликам
```

## Ответственности

- `backend/schemas.py` — схемы входов и выходов, ограничения размеров.
- `backend/ai_service.py` — OpenAI, промпт, проверка результата, явный режим demo,
  ограниченные повторы, таймаут и отсутствие придуманных полей в шаблоне.
- `backend/scoring.py` — чистый детерминированный расчёт.
- `backend/main.py` — HTTP-контракты FastAPI.
- `frontend/lib/backend-client.ts` — серверный адаптер Python API; проверяет формат,
  таймауты и ошибки зависимости. Браузеру не нужен адрес Python или OpenAI-ключ.
- `frontend/lib/validation.ts` — проверка пользовательского ввода и подтверждения.
- `frontend/lib/task-service.ts` — сценарии публикации, пересчёта и ручного выбора.
- `frontend/lib/store.ts` — прежняя реализация локального демохранилища, без изменений.
- `frontend/lib/api.ts` — браузерный транспорт с таймаутом и понятными ошибками.
- `frontend/components/card-editor.tsx` — редактирование, отмена устаревших запросов
  скоринга и ручное подтверждение. После правки подтверждение сбрасывается.

Формула рейтинга не дублируется в TypeScript. Функции с одной ответственностью
используются там, где нет состояния; отдельный класс `AppError` описывает ожидаемые
ошибки. Наследование ради формального соблюдения ООП не добавлено.

## Контракты

| Вызов браузера через Next.js | Назначение |
|---|---|
| GET `/api/health` | Доступность Python и режим AI |
| POST `/api/ai/clarify` | `{draft_text}` → `{questions, mode}` |
| POST `/api/ai/build-card` | `{draft_text, qa_pairs:[{question,answer}]}` → `{card_data, scoring, mode}` |
| POST `/api/tasks/score` | `{card_data}` → `{score,status,breakdown,missing_fields}` |
| POST `/api/tasks` | `{card_data,confirmed:true}` → опубликованная задача, HTTP 201 |
| PATCH `/api/tasks/:id` | `{card_data,confirmed:true}` → обновлённая задача с новым рейтингом |
| GET `/api/tasks` | Все опубликованные задачи, по убыванию рейтинга |
| GET `/api/tasks/:id` | Карточка с актуальным рейтингом |
| POST `/api/applications` | `{task_id,team_name,idea,plan,deadline,prototype?}` → отклик |
| GET `/api/tasks/:id/applications` | Отклики без ограничения после выбора команды |
| PATCH `/api/applications/:id/status` | `{status:"ACCEPTED" или "REJECTED"}` → ручное решение |

Frontend сохраняет прежние названия `data` / `criteria`; адаптер сопоставляет их с
`data_materials` / `success_criteria` Python. Поля `expected_result`, `target_audience`,
`interaction_format` теперь присутствуют в интерфейсе. Отсутствующее значение из AI
(`null`) превращается в пустое редактируемое поле, а не в строку «null».
Компания, направление и ссылка — дополнительные поля каталога, без баллов.

Для Python `POST /api/ai/score` принимает непосредственно TaskCard. Все пустые
поля допускаются, кроме названия; при пустом названии в предварительном просмотре
адаптер использует нейтральный текст без добавления баллов. Публикация отдельно
требует настоящих непустых названия и контекста и подтверждения человеком.

## Рейтинг и выбор

Контекст 20, данные 20, результат 15, критерии 15, ограничения 10, аудитория 10,
связь с бизнесом 10. После удаления крайних пробелов: менее 10 символов — 0,
10–29 — половина с округлением вниз, от 30 — максимум. Связь разделена на контакты
и консультации по 5 баллов. Это приближение по длине, не семантическая экспертиза.

0–39 DRAFT; 40–69 WORKING; 70–89 READY; 90–100 PRIORITY. Предварительный расчёт
не меняет каталог до подтверждения. При публикации сервер пересчитывает рейтинг
сам и не доверяет присланному `score`. Чтение старых карточек нормализует новые
поля и пересчитывает рейтинг, не записывая изменения в хранилище.

Низкий балл не запрещает отклик. Принятие одной команды не блокирует остальные.
Повтор идентичного решения безопасен; противоположное решение по рассмотренному
отклику возвращает 409. Авторизация и разграничение владельцев ещё не реализованы.

## Ошибки и ограничения

400 — неверный JSON; 413 — тело свыше 512000 байт на Next-маршруте; 415 — неверный
Content-Type; 422 — поля/подтверждение; 404 — объект отсутствует; 409 — конфликт
решения; 502 — некорректный ответ зависимости; 503 — недоступность; 504 — таймаут;
500 — внутренняя ошибка без раскрытия путей и содержимого хранилища.

Next ограничивает длины полей, Python повторно валидирует свой контракт. AI-запрос
ограничен общим таймаутом 65 секунд, транспорт Next — 70, браузер — 75. Запросы
оценки имеют отдельный таймаут 10 секунд. Нет автоматических повторов публикации
и отклика, которые могли бы незаметно создать дубликаты.
