# Практика

Интерфейс для бизнеса и студенческих команд: Next.js App Router, React, TypeScript, адаптивный CSS.

## Запуск

Требуется Node.js 20.9+.

Сначала запустите Python backend по инструкции в `../backend/README.md` и задайте ему `OPENAI_API_KEY`. Затем создайте `frontend/.env.local`:

```env
SESSION_SECRET=случайная-строка-не-короче-32-символов
AI_BACKEND_URL=http://127.0.0.1:8000
```

Секрет сессии должен быть случайным и постоянным между перезапусками. Из папки `frontend`:

```sh
npm install
npm run dev
```

Запускайте команды из папки `frontend`. Откройте http://localhost:3000/catalog. Для production: `npm run build`, затем `npm start`.

## Экраны

- `/catalog` — поиск, направления, статусы, минимальный балл; по умолчанию сортировка по убыванию готовности.
- `/create-task` — черновик → три уточнения → редактирование и живой скоринг → публикация.
- `/tasks/[id]` — полная карточка и отправка отклика в роли студента.
- `/my-tasks` — кабинет с задачами текущего пользователя.
- `/my-tasks/[id]/apps` — рассмотрение откликов. После принятия команды остальные действия блокируются и в интерфейсе, и в API.

Вход по email и паролю создаёт серверную сессию в HttpOnly cookie. Создавать задачи, отправлять отклики и просматривать их можно только после входа. Отклики и решение по команде доступны владельцу задачи. Переключатель роли влияет только на подсказки интерфейса. Это временная локальная авторизация; перед публичным запуском нужны защита от перебора паролей, восстановление доступа, подтверждение email и постоянная база данных.

## API и данные

Все эндпоинты ТЗ реализованы в `app/api/[...path]/route.ts`. Дополнительно доступны `GET /api/tasks/:id`, `GET /api/tasks/:id/applications` и `POST /api/tasks/score`.

Карточка: `title`, `company`, `category`, `context`, `data`, `expected_result`, `constraints`, `criteria`, `target_audience`, `contacts`, `interaction_format`, `links` (строки). Отклик: `task_id`, `team_name`, `idea`, `plan`, необязательный `prototype`. Статусы отклика: PENDING, ACCEPTED, REJECTED.

`/api/ai/clarify` и `/api/ai/build-card` обращаются к Python backend через серверный прокси. Он принимает `draft_text` и `qa_pairs`; ответ `card` преобразуется в поля редактора. Ошибки backend показываются в интерфейсе. Без доступного backend или API-ключа AI-шаги не работают.

Задачи и отклики сохраняются в `.data/store.json`; на первом запуске доступны шесть демозадач. Записи сериализованы внутри одного Node.js-процесса. Это локальное хранилище для демо, не база данных для нескольких процессов или serverless. Для сброса демоданных остановите приложение и удалите этот файл.

Скоринг (`lib/domain.ts`) повторяет Python backend: для каждого поля меньше 10 символов — 0 баллов, 10–29 — половина с округлением вниз, 30 и больше — полный вес. DRAFT <40, WORKING 40–69, READY 70–89, PRIORITY ≥90. Компания, направление и ссылка остаются метаданными каталога и не оцениваются.

Существующие шесть демозадач и ранее созданные задачи без владельца видны в каталоге, но закрыты для новых откликов. Их нельзя автоматически привязать к новому пользователю без доказательства владения.

## Проверки

```sh
npm test
npm run typecheck
npm run build
```

Ручной сценарий: создайте задачу, переключитесь на студента, отправьте два отклика разными командами, откройте задачу в кабинете бизнеса и примите одну команду. Проверьте блокировку второго отклика и сохранение после перезагрузки.
