# Практика

Интерфейс для бизнеса и студенческих команд: Next.js App Router, React, TypeScript, PostgreSQL и Prisma ORM 7.

## Запуск

Требуются Node.js 22.12+ (рекомендуется Node.js 24 LTS), npm, PostgreSQL 14+ и pgAdmin 4. PostgreSQL должен быть запущен.

### 1. Установите зависимости

Команды ниже выполняются из корня репозитория:

```sh
cd frontend
npm install
```

Все следующие команды запускайте из `frontend`. При установке автоматически генерируется Prisma Client; подключение к базе на этом шаге не требуется.

### 2. Создайте базу через pgAdmin

1. Откройте pgAdmin и подключитесь к локальному серверу PostgreSQL (обычно `localhost`, порт `5432`, пользователь `postgres`). Введите пароль, заданный при установке PostgreSQL.
2. В дереве слева откройте **Servers → ваш сервер → Databases**.
3. Нажмите правой кнопкой на **Databases → Create → Database…**.
4. В поле **Database** укажите `praktika`, в **Owner** выберите `postgres` и нажмите **Save**.

### 3. Создайте локальный `.env`

PowerShell:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

macOS/Linux: `cp .env.example .env`, затем откройте `.env` в редакторе. Если `.env` уже существует, отредактируйте его, не копируйте шаблон поверх.

Замените `ВАШ_ПАРОЛЬ` своим паролем PostgreSQL:

```ini
DATABASE_URL="postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/praktika?schema=public"
```

Если пароль содержит специальные символы (`@`, `:`, `/`, `#`, `%` и другие), закодируйте их для URL (например, `@` → `%40`). `.env` исключён из Git. В репозитории хранится только `.env.example` без настоящих паролей.

Для регистрации и входа задайте в том же `.env` постоянный случайный `SESSION_SECRET` длиной не меньше 32 символов. Сгенерировать значение можно командой ниже; скопируйте результат в `.env`, не добавляйте его в Git:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

`AI_BACKEND_URL` по умолчанию равен `http://127.0.0.1:8000`. Для AI-шагов отдельно запустите Python backend по инструкции в `../backend/README.md` и задайте ему `OPENAI_API_KEY`. Если секрет сессии уже указан в `.env.local`, сохраните существующее значение: Next.js отдаёт `.env.local` приоритет над `.env`.

### 4. Примените миграции, заполните базу и запустите приложение

```sh
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте [каталог задач](http://localhost:3000/catalog). Seed добавляет шесть задач из `seedTasks()` со стабильными ID; повторный запуск не создаёт дубликаты, не перезаписывает существующие задачи и не удаляет отклики.

Для production:

```sh
npm run db:migrate
npm run build
npm start
```

`npm run db:generate` вручную обновляет Prisma Client. После изменения схемы создавайте новую миграцию командой `npx prisma migrate dev --name имя_изменения` (для этого PostgreSQL-пользователю нужна возможность создавать shadow database). Для применения готовых миграций используйте `npm run db:migrate`. Частичный уникальный индекс хранится в SQL-миграции; не заменяйте миграции командой `prisma db push`.

## Экраны

- `/catalog` — поиск, направления, статусы, минимальный балл; по умолчанию сортировка по убыванию готовности.
- `/create-task` — черновик → три уточнения → редактирование и живой скоринг → публикация.
- `/tasks/[id]` — полная карточка и отправка отклика в роли студента.
- `/my-tasks` — кабинет с задачами текущего пользователя.
- `/my-tasks/[id]/apps` — рассмотрение откликов. После принятия команды остальные действия блокируются и в интерфейсе, и в API.

Вход по email и паролю создаёт подписанную сессию в HttpOnly cookie. Пользователи и хеши паролей хранятся в PostgreSQL. Создавать задачи, отправлять отклики и просматривать их можно только после входа. Отклики и решение по команде доступны владельцу задачи. Переключатель роли влияет только на подсказки интерфейса. Перед публичным запуском нужны защита от перебора паролей, восстановление доступа и подтверждение email.

## API и данные

Все эндпоинты ТЗ реализованы в `app/api/[...path]/route.ts`. Дополнительно доступны `GET /api/tasks/:id`, `GET /api/tasks/:id/applications` и `POST /api/tasks/score`.

Карточка: `title`, `company`, `category`, `context`, `data`, `expected_result`, `constraints`, `criteria`, `target_audience`, `contacts`, `interaction_format`, `links` (строки). Отклик: `task_id`, `team_name`, `idea`, `plan`, необязательный `prototype`. Статусы отклика: PENDING, ACCEPTED, REJECTED.

`/api/ai/clarify` и `/api/ai/build-card` обращаются к Python backend через серверный прокси. Он принимает `draft_text` и `qa_pairs`; ответ `card` преобразуется в поля редактора. Ошибки backend показываются в интерфейсе. Без доступного backend или API-ключа AI-шаги не работают.

Данные сохраняются в PostgreSQL через `lib/store.ts` и общий Prisma Client из `lib/prisma.ts`. Схема содержит `Task`, `Application` и `User`. `Application.taskId` ссылается на задачу с `ON DELETE CASCADE`; необязательный `Task.ownerId` ссылается на пользователя с `ON DELETE SET NULL`. API сохраняет поля задачи внутри `card_data`, `created_at` у задачи, `task_id` и `team_name` у отклика. Дополнительно задача возвращает `owner_id` и `applications_open`; `GET /api/my-tasks` выдаёт только задачи текущего пользователя.

Исходные миграции сохранены. Новые миграции добавляют поля карточки backend и статус `DRAFT`, пересчитывают производные `score`/`status`, затем создают `User` и необязательную связь владельца с задачами. Они не удаляют задачи или отклики, не меняют их ID, содержимое и выбранные команды. Существующим задачам владелец автоматически не назначается. Для обновления существующей базы достаточно `npm run db:migrate`; сброс базы не нужен.

Создание отклика и изменение его статуса проходят в транзакции с блокировкой строки задачи `SELECT … FOR UPDATE`. Поэтому после выбора команды блокируются новые отклики и последующие решения даже при запросах из разных процессов. Дополнительно частичный уникальный индекс `Application_one_accepted_per_task` запрещает больше одного `ACCEPTED` для одной задачи на уровне PostgreSQL. При конкурирующих принятиях один запрос успешен, второй получает HTTP 409. Отклонённых и ожидающих откликов может быть несколько.

Файл `.data/store.json` больше не читается и не изменяется. Существующие пользовательские записи из него автоматически не импортируются; seed переносит только шесть исходных демонстрационных задач. После миграций и до seed новая база пуста.

Скоринг (`lib/domain.ts`) повторяет Python backend: для каждого поля меньше 10 символов — 0 баллов, 10–29 — половина с округлением вниз, 30 и больше — полный вес. DRAFT <40, WORKING 40–69, READY 70–89, PRIORITY ≥90. Компания, направление и ссылка остаются метаданными каталога и не оцениваются.

Существующие шесть демозадач и ранее созданные задачи без владельца видны в каталоге, но закрыты для новых откликов. Их нельзя автоматически привязать к новому пользователю без доказательства владения.

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

Без `TEST_DATABASE_URL` запускаются проверки доменной логики, валидации и вспомогательных API; интеграционный набор явно пропускается. Для полной проверки создайте через pgAdmin отдельную базу `praktika_test` и в текущей сессии PowerShell задайте строку подключения:

```powershell
$env:TEST_DATABASE_URL = 'postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/praktika_test?schema=public'
npm test
Remove-Item Env:TEST_DATABASE_URL
```

Интеграционный набор создаёт уникальную временную схему в указанной базе и удаляет только эту схему в конце. Пользователь должен иметь право создавать схемы. Сначала применяются две исходные миграции и создаются тестовые задачи с откликами, затем новые миграции проверяются на сохранение этих данных. Также проверяются seed, регистрация/вход, проверка владельца, личный кабинет, отклики, одновременные решения, уникальный индекс при прямых конкурентных записях и каскадное удаление. AI-тесты используют подставной backend без сетевых вызовов и API-ключа. Для `typecheck` и `build` работающая база не требуется.

Ручной сценарий: создайте задачу, переключитесь на студента, отправьте два отклика разными командами, откройте задачу в кабинете бизнеса и примите одну команду. Проверьте блокировку второго отклика и сохранение после перезагрузки.
