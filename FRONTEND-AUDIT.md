## Найденные проблемы

### P1 — Нет серверной авторизации и проверки владельца (известное ограничение демо)

`frontend/app/api/[...path]/route.ts:6,12,14`, `frontend/components/workspace.tsx:13`.

HTTP-запрос без cookie/token успешно создал отклик и принял его через PATCH `/api/applications/:id/status` (200, ACCEPTED). GET выдаёт отклики без проверки прав. Переключатель роли влияет только на отображение. Любой посетитель может выбрать исполнителя чужой задачи. README открыто описывает отсутствие авторизации; для публичного сервиса это блокер.

### P2 — Форма отклика активна после выбора исполнителя

`frontend/components/workspace.tsx:22`, `frontend/lib/domain.ts:2`.

Подтверждено в браузере: после принятия команды на задачу 1 её карточка продолжает показывать поля и кнопку «Отправить отклик». Повторный POST возвращает 400 «Команда уже выбрана». В Task отсутствует признак закрытого набора; UI не запрашивает его отдельно. Пользователь тратит время на форму, которую невозможно отправить. Добавить в контракт признак доступности отклика и показывать закрытый набор до заполнения формы.

### P2 — Кабинет бизнеса скрывает ошибки загрузки

`frontend/components/workspace.tsx:14,19`.

Обнаружено по коду: ветка `myTasks` выводится раньше обработки `loading` и `error` и только перебирает `tasks`. При первом сбое GET `/api/tasks` пользователь получает пустой кабинет без сообщения и кнопки повтора; при ранее загруженных данных могут отображаться устаревшие задачи. Отдельная runtime-инъекция сбоя не проводилась.

### P2 — Возврат назад из редактора уничтожает ручные правки

`frontend/components/workspace.tsx:20–21`.

Обнаружено по коду: на шаге 3 изменить компанию, контакты или название → «Назад» → «Сформировать карточку». Обработчик шага 2 повторно вызывает build-card и безусловно делает `setCard(r.card_data)`, заменяя отредактированную карточку шаблоном. Нужно сохранять правки или явно предупреждать о пересоздании. Браузерное воспроизведение этого сценария не проводилось.

### P2 — Неверные URL открывают настоящие карточки

`frontend/components/workspace.tsx:16,19`, `frontend/app/[[...slug]]/page.tsx:2`.

Подтверждено HTTP и браузером: `/garbage/1` возвращает 200 и показывает задачу 1. ID извлекается через `path.split('/')[2]` без проверки шаблона `/tasks/:id`; catch-all принимает любой маршрут. Нужна явная валидация маршрута и корректная 404.

## Совместимость API

С локальным API этой ветки запросы и ответы согласованы:

| Запрос | Фронтенд / локальный API |
| --- | --- |
| GET `/api/tasks` | `Task[]`, вложенная `card_data`, `score`, `status`, `created_at` |
| POST `/api/ai/clarify` | `{draft_text}` → `{questions, mode}` |
| POST `/api/ai/build-card` | `{draft, answers}` → `{card_data, mode}` |
| POST `/api/tasks` | `{card_data}` → созданная задача |
| POST `/api/applications` | `{task_id, team_name, idea, plan, prototype}` → отклик |
| GET `/api/tasks/:id/applications` | `Application[]` |
| PATCH `/api/applications/:id/status` | `{status}` → `{success, application}` |

Ограничения интеграции:

- Отдельного backend-кода, OpenAPI и удалённой backend-ветки не найдено после `git fetch origin`. Совместимость с отдельным бэкендом НЕ подтверждена.
- Все URL относительные `/api/...`; в next.config нет прокси/rewrites на отдельный backend.
- Скоринг в редакторе выполняется локально `scoreCard`; существующий POST `/api/tasks/score` UI не использует. При смене серверной формулы возможны разные значения до и после публикации.
- UI ожидает JSON даже при ошибках. HTML-ошибка прокси или пустой ответ приведут к ошибке JSON-разбора вместо понятного сообщения.
- AI — шаблонные заглушки; хранилище — `.data/store.json`, рассчитанное на один процесс. Это документированные ограничения демо, а не подтверждение готовности внешнего backend.

Для завершения внешней интеграционной проверки нужен код/ветка или адрес backend и его контракт API.

### Подтверждённые расхождения

| Область | Фронтенд / встроенный Next.js API | Python backend |
| --- | --- | --- |
| Подключение | Относительные `/api/ai/*` перехватываются `frontend/app/api/[...path]/route.ts`; прокси нет | Отдельный FastAPI на порту 8000 |
| `build-card` запрос | `{draft: string, answers: string[3]}` | `{draft_text: string, qa_pairs: {question, answer}[]}` |
| `build-card` ответ | `{card_data: Card, mode}` | `{card: TaskCard, scoring: ScoringResult}` |
| Карточка | `company`, `category`, `data`, `criteria`, `links`, все поля строковые | `data_materials`, `expected_result`, `success_criteria`, `target_audience`, `interaction_format`, необязательные поля могут быть `null`; `company/category/links` отсутствуют |
| Скоринг | Баллы за непустые поля; PRIORITY от 85; нет DRAFT | Зависит от длины текста; PRIORITY от 90; DRAFT ниже 40 |
| Ошибки | UI читает `data.error` | FastAPI отдаёт `detail` |
| Задачи и отклики | Создание и хранение во встроенном Next.js API | В Python backend этих эндпоинтов нет |

Следствие: текущий фронтенд работает со своим демо API, но не совместим с добавленным Python backend без адаптера и согласования общей схемы карточки и скоринга. Старую фразу выше о ненайденном бэкенде следует читать как историческое состояние до `git pull`.
