# Проверка пилота на ветке main

Дата: 23 сентября 2026. Проверена связка Next.js 16.3.6 + FastAPI,
Python 3.14 и Node.js 24.19 на Windows. Проверка функциональная, не нагрузочная.

## Найдено и исправлено

| Проблема до проверки | Исправление |
|---|---|
| Фронтенд не обращался к Python AI | Серверный адаптер Next → FastAPI, согласованные draft_text/qa_pairs и card/scoring |
| Разные формулы баллов и порог 85 вместо 90 | Единственный расчёт в Python для предпросмотра, публикации и каталога |
| Отсутствовал статус DRAFT | Добавлен в карточки и фильтры; слабая задача остаётся доступной |
| Не было результата, аудитории, формата консультаций | Добавлены отдельные редактируемые поля и отображение |
| Нет явного подтверждения и редактирования после публикации | Подтверждение перед записью, сброс галочки после правок, пересчёт после сохранения |
| Выбор одной команды блокировал всех | Можно принять несколько, отклонить остальные и продолжать получать отклики |
| Ошибки запроса/хранилища смешивались, раскрывались детали | Классификация 400/404/409/413/415/422/500/502/503/504, безопасные сообщения |
| Невалидный ответ зависимости мог попасть в UI | Проверка вопросов, карточки, баллов и соответствия статуса |
| Нет общего срока ожидания в браузере | Ограниченные таймауты, отмена устаревших запросов рейтинга |
| Инструкция описывала старый несвязанный деморежим | Обновлён запуск двух сервисов, сценарии и архитектура |

## Автоматические проверки

- Python: **12 тестов прошли**, включая перебор **6561** комбинации, границы длины и
  статусов, CORS, ошибки OpenAI, null без выдуманных значений, score endpoint и режимы AI.
- TypeScript / интеграция: **12 проверок прошли**. Тест запускает настоящий Python,
  вызывает Next HTTP-обработчики и использует изолированную папку прежнего хранилища.
- Production-сборка Next.js, включая проверку TypeScript: успешно.
- Форматирование изменений Git: без ошибок.

Проверены неверный JSON, null/массив/число вместо объекта, неверные типы и размеры
полей, слишком большое тело, неверный Content-Type, опасная ссылка, неизвестная
задача/отклик, повтор и конфликт решения, неверный JSON/схема зависимости, таймаут,
обрыв соединения, ошибка чтения демохранилища без раскрытия внутреннего содержимого.

Тест публикации подставляет `score:100` при слабой карточке: сервер возвращает
рассчитанные **10**, а не доверяет клиенту. После подтверждённой правки карточка
получает **100** и поднимается в каталоге. Автотесты не изменяют пользовательские записи.

## Проверка в браузере

На production-сборке локально пройден реальный интерфейс:

1. Черновик «Нужно разобраться в продажах» → три вопроса → три ответа → **60/100**.
2. Дополнение оставшихся полей → **100/100** → подтверждение → публикация.
3. Новая задача заняла первое место в каталоге.
4. Две синтетические команды отправили отклики; показано подтверждение отправки.
5. Бизнес вручную принял обе команды; после перезагрузки оба решения сохранились.
6. Удаление материалов в редакторе → **80/100**, статус READY после подтверждения.
7. Восстановление материалов → **100/100**, статус PRIORITY.
8. В журнале браузера на этом сценарии ошибок не обнаружено.

В локальном демохранилище оставлен пример «Пилот: дашборд продаж кофейни» и два
синтетических отклика для ручного просмотра. Эти данные игнорируются Git.

## Границы результата

Новая БД, слой хранения и миграции не добавлялись; `frontend/lib/store.ts` не менялся.
Платные запросы OpenAI не выполнялись: его SDK проверен с подставным транспортом,
браузерный сценарий — с явно включённым AI_MODE=demo. Качество вопросов настоящей
модели требует отдельной проверки на ключе.

Не реализованы авторизация/права владельца, баллы за этапы, полный набор профилей
команд, сохранение незавершённой формы и идемпотентность публикации/отклика после
потери ответа. Не проверялись многопроцессное хранение, нагрузка и все браузеры.
Существует предупреждение тестового Starlette TestClient о будущей замене httpx;
оно не мешает прохождению проверок, но требует внимания при обновлении зависимостей.

Работающие проверенные сценарии не означают отсутствия всех возможных ошибок.
Приоритеты закрытия оставшихся требований приведены в [плане MVP](MVP_NEXT_STEPS.md).
