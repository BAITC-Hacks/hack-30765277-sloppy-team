# Пилот «Практика»: инструкция для бизнеса и студентов

Пилот проверяет путь от черновика до публикации, отклика и ручного решения бизнеса.
Все примеры ниже синтетические. Переключатель «Студент / Бизнес» меняет интерфейс,
но не является авторизацией: кабинет бизнеса общий. Используйте локально или на
закрытой демонстрации, без персональных данных.

## Запуск

Требуются Python 3.11+ и Node.js 20.9+ с npm. Откройте два терминала из корня проекта.

Терминал 1 — бэкенд, PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:AI_MODE = "demo"
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Терминал 2 — фронтенд:

```powershell
cd frontend
npm ci
$env:BACKEND_URL = "http://127.0.0.1:8000"
npm run dev
```

Откройте http://localhost:3000/catalog. Состояние связи доступно на
http://localhost:3000/api/health, документация Python API — http://127.0.0.1:8000/docs.
Если порт занят, задайте другой порт в команде бэкенда и тот же адрес в `BACKEND_URL`.

В `AI_MODE=demo` внешний ИИ не вызывается: три фиксированных вопроса и перенос
ответов позволяют пройти весь сценарий без ключа. Режим явно обозначен в мастере.
Для настоящего ИИ перезапустите бэкенд с `AI_MODE=openai` и переменной
`OPENAI_API_KEY`. Ключ нужен только Python-сервису; не добавляйте его в исходники
или `NEXT_PUBLIC_*`. `.env` Python автоматически не загружает. Ошибка внешнего
ИИ показывается пользователю; скрытой подмены на деморежим нет.

## Проверка глазами бизнеса

1. Нажмите «Бизнес», затем «Создать задачу».
2. Введите слабый черновик: **Нужно разобраться в продажах**.
3. Нажмите «Уточнить задачу». В деморежиме ответьте:

| Вопрос | Текст ответа |
|---|---|
| Конкретный результат | Дашборд продаж с фильтрами по дням и товарам |
| Данные и материалы | Обезличенные таблицы продаж за последние шесть месяцев |
| Признаки приёмки | Суммы в отчёте совпадают с исходными таблицами |

4. Нажмите «Сформировать карточку». В деморежиме ожидаемый рейтинг — **60/100**.
   Контакты, аудитория и ограничения должны остаться пустыми: помощник их не придумывает.
5. Откройте «Расшифровка рейтинга» и «Как повысить рейтинг». Дополните карточку:

| Поле | Синтетический пример |
|---|---|
| Название | Пилот: дашборд продаж кофейни |
| Компания | Учебная кофейня |
| Контекст | Продажи учитываются в таблицах, владельцу сложно сравнивать спрос по дням и товарам. |
| Ограничения | Прототип нужен за четыре недели, только обезличенные данные и открытые инструменты. |
| Пользователи / ЦА | Владелец кофейни и администратор смены анализируют продажи каждый вечер. |
| Контакт | Учебный координатор бизнеса: pilot@example.com |
| Формат консультаций | Консультация раз в неделю, обратная связь по прототипу в течение двух рабочих дней. |

6. Ожидайте **100/100**. Баллы рассчитываются на сервере; название и компания сами по
   себе баллов не добавляют. Галочка подтверждения сбрасывается при изменении поля.
7. Отметьте «Я проверил карточку…» и нажмите «Опубликовать в каталог». Без подтверждения
   публикация недоступна. Найдите задачу через поиск — статус «В приоритете».
8. Откройте её в роли бизнеса и нажмите «Редактировать карточку». Удалите данные и
   материалы, подтвердите изменения: рейтинг станет **80**, статус — «Готова к работе».
   Верните поле и подтвердите: снова **100**. Каталог сортируется по новому рейтингу.

Дополнительная проверка: создайте задачу с тем же коротким черновиком и пустыми
ответами. После ручного подтверждения она публикуется с **10 баллами**, пометкой
«Требует уточнения» и остаётся доступной для откликов.

## Проверка глазами студента

1. Переключитесь на «Студент». Откройте каталог, попробуйте поиск, направление,
   статус и минимальную готовность. Фильтры добровольные; «Любой балл» включает слабые задачи.
2. Откройте «Пилот: дашборд продаж кофейни». Прочитайте поля, баллы и рекомендации.
3. Заполните отклик:
   - Команда: **Команда Альфа**.
   - Идея: **Построим дашборд с динамикой продаж и сравнением категорий.**
   - План: **Неделя 1 — проверка данных; 2 — расчёты; 3 — интерфейс; 4 — проверка с бизнесом.**
   - Предлагаемый срок: **Четыре недели после получения данных**.
   - Ссылка на прототип: оставьте пустой или используйте `https://example.com/prototype`.
4. Нажмите «Отправить отклик». Должно появиться сообщение «Отклик отправлен!».
5. Вернитесь в каталог, откройте задачу снова и отправьте предложения от команд
   **Бета** и **Гамма** с другими идеями. Это имитация нескольких команд без регистрации.
6. Попробуйте откликнуться на задачу с 10 баллами — низкий рейтинг не должен запрещать отправку.

## Решение бизнеса

1. Переключитесь на «Бизнес», откройте «Кабинет бизнеса», затем отклики на вашу задачу.
2. Сравните идеи, планы, сроки и ссылки. Примите Альфу, примите Бету и отклоните Гамму.
   Можно выбрать несколько команд, одну или не выбирать никого. Автоматического назначения нет.
3. Перезагрузите страницу: решения остаются видны. Рассмотренный отклик нельзя
   перевести в противоположный статус; повтор того же запроса безопасен.
4. Новый отклик после выбора команд по-прежнему разрешён.

Баллы студентам за подтверждённые этапы в текущем пилоте ещё не начисляются.

## Ошибки, которые стоит попробовать

| Проверка | Ожидаемый результат |
|---|---|
| Пустой черновик | Запрос не отправляется / сервер отклоняет ввод |
| Нет ответа на уточнение | Допускается; отсутствующие данные остаются пустыми |
| `javascript:alert(1)` вместо ссылки | Валидация отклоняет ссылку |
| Остановлен Python | Понятное сообщение о соединении и возможность повторить |
| OpenAI без ключа в режиме openai | Сообщение о настройке сервиса, без вымышленной карточки |
| Изменение после установки галочки | Требуется повторное подтверждение |
| Повторное принятие того же отклика через API | Успех без повторного изменения |
| Принятый отклик пытаются отклонить | Конфликт 409 |

Не обновляйте страницу, пока вводите длинный черновик: автоматического сохранения
незавершённой формы пока нет. Сохранённые задачи и отклики использует прежнее локальное
демохранилище `frontend/.data/store.json`; его реализация в этой работе не менялась.

## Демонстрация за пять минут

0:00–1:00 — короткий черновик и три ответа. 1:00–2:00 — карточка, расшифровка,
рост 60 → 100 и подтверждение. 2:00–3:00 — публикация и выбор задачи студентом.
3:00–4:00 — отклики двух команд. 4:00–5:00 — ручное решение бизнеса, повторное
открытие каталога и объяснение, почему слабые задачи остаются доступными.
